# تجهيز Supabase لعيادة د. أشرف أبو عابد

هذا الدليل خطوة بخطوة. كل خطوة تقريبًا عبارة عن ضغطات في موقع Supabase، ولا تحتاج برمجة.

## الخطوة 1: إنشاء الحساب والمشروع (10 دقائق)

1. ادخل إلى **supabase.com** واضغط **Start your project**. سجّل بحساب GitHub أو بالبريد.
2. اضغط **New project**:
   - **Name:** `smile-clinic`
   - **Database Password:** اضغط **Generate a password**، ثم **احفظها في مكان آمن** (مدير كلمات مرور أو ورقة في خزنة). **لا ترسلها لأحد، ولا لي.**
   - **Region:** اختر **Central EU (Frankfurt)**. هي الأقرب، ولا توجد منطقة داخل إسرائيل.
3. انتظر دقيقتين حتى يجهز المشروع.
4. من **Organization → Billing** رقِّ الخطة إلى **Pro** قبل إدخال أي بيانات حقيقية.

## الخطوة 2: إنشاء قاعدة البيانات (دقيقتان)

1. من القائمة الجانبية افتح **SQL Editor** ثم **New query**.
2. افتح الملف `supabase/schema.sql`، وانسخ **كل** محتواه، والصقه في المحرر.
3. اضغط **Run**. يجب أن تظهر رسالة **Success. No rows returned**.

> هذا الملف جرّبته على PostgreSQL حقيقي بـ 38 اختبار أمان، ونجحت كلها. من بينها:
> - السكرتيرة لا ترى الأرباح.
> - عيادة لا ترى بيانات عيادة أخرى.
> - من فعّل التحقق بخطوتين لا يرى شيئًا قبل إدخال الرمز.
> - لا يمكن تعديل مبلغ بعد حفظه.
> - لا شيء يُحذف نهائيًا.

## الخطوة 3: إعدادات الدخول والأمان (5 دقائق)

من **Authentication**:

1. **Sign In / Providers → Email:** اتركه مفعّلًا، و**أوقف Allow new users to sign up**. لا أحد يستطيع إنشاء حساب بنفسه، فقط الطبيب يضيف فريقه.
2. **Multi-Factor:** تأكد أن **TOTP (App Authenticator)** مفعّل. هو مفعّل عادةً، وهو مجاني.
3. **Passwords** (إن كانت متوفرة في خطتك):
   - الحد الأدنى للطول: **8**.
   - فعّل **Leaked password protection** إن ظهر.
4. **Emails → SMTP Settings:** لإرسال رسائل البريد (استعادة كلمة المرور، دعوة السكرتيرة) من بريد العيادة:
   - أنشئ حسابًا مجانيًا في **resend.com**، وأضف نطاق العيادة إن وُجد.
   - انسخ إعدادات SMTP من Resend إلى هنا.
   - بدون هذه الخطوة يرسل Supabase عددًا قليلًا جدًا من الرسائل في الساعة، وهذا للتجربة فقط.

## الخطوة 4: حساب الطبيب (دقيقتان)

1. **Authentication → Users → Add user → Create new user:**
   - البريد: `aliafawi116@gmail.com` (أو بريد الطبيب)
   - كلمة مرور قوية، وفعّل **Auto Confirm User**.
2. ارجع إلى **SQL Editor** وشغّل (عدّل الاسمين):

```sql
select public.setup_owner('aliafawi116@gmail.com', 'מרפאת ד״ר אשרף אבו עאבד', 'ד״ר אשרף אבו עאבד');
```

## الخطوة 5: ما ترسله لي

من **Project Settings → API**:

- **Project URL** (مثل `https://abcd1234.supabase.co`)
- **anon / publishable key**

هذان **آمنان للمشاركة**، فهما مكتوبان أصلًا داخل أي موقع يستخدم Supabase. الحماية الحقيقية في قواعد قاعدة البيانات التي أنشأناها.

**لا ترسل أبدًا:**
- كلمة مرور قاعدة البيانات
- مفتاح `service_role` / `secret`
- أي كلمة مرور لحساب

## الخطوة 6: النسخة الليلية المقفلة (15 دقيقة، مرة واحدة)

هذه هي الطبقة التي تحمي البيانات حتى لو حدث خطأ كبير في Supabase نفسه.

1. **Backblaze B2** (backblaze.com):
   - أنشئ Bucket خاصًا (Private) وفعّل **Object Lock** مع مدة احتفاظ (مثلًا سنة واحدة).
   - أنشئ Application Key لهذا الـ Bucket فقط.
2. **مستودع GitHub خاص** للمشروع، وفيه الملف `.github/workflows/nightly-backup.yml`.
3. أضف الأسرار (Secrets) المذكورة في أعلى ذلك الملف من **Settings → Secrets and variables → Actions**.
4. شغّله يدويًا مرة من تبويب **Actions** وتأكد أنه أخضر.
5. **مرة كل 3 أشهر:** جرّب استرجاع نسخة. النسخة التي لم تُجرَّب استعادتها لا يُعتمد عليها.

> اكتب **BACKUP_PASSPHRASE** على ورقة واحفظها مع أوراق العيادة المهمة. بدونها لا يمكن فتح النسخ.

## ما الذي تغيّر عن المحاكاة؟

| | المحاكاة الحالية | مع Supabase |
|---|---|---|
| أين البيانات | متصفح واحد | خادم في فرانكفورت، من أي جهاز |
| الصلاحيات | تُخفي الأزرار فقط | **قاعدة البيانات نفسها ترفض** |
| التحقق بخطوتين | يعمل في المتصفح | Supabase يتحقق، وقاعدة البيانات تشترط مستوى الدخول aal2 |
| صور الأشعة | المتصفح | تخزين خاص لكل عيادة، لا يمكن حذفه من التطبيق |
| النسخ الاحتياطي | ملف يدوي | يومي في Supabase، وليلي مقفل في B2، وشهري بين يديك |

## المرحلة القادمة (عملي أنا)

بعد أن ترسل لي Project URL والمفتاح:

1. أربط الموقع بـ Supabase: الدخول، التحقق بخطوتين، كل الصفحات، رفع الأشعة.
2. أكتب دالة خادم صغيرة لزر «إضافة سكرتيرة»، لأن إنشاء حساب يحتاج صلاحية لا تُعطى للمتصفح.
3. أنشر الموقع على Cloudflare Pages برابط خاص بالعيادة.

**ملاحظة:** صفحة المحاكاة في Claude لا تستطيع الاتصال بخوادم خارجية، لذلك الموقع الحقيقي سيكون على رابط مستقل.
